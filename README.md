# 행정누리

통합 행정업무 시스템 **행정누리**입니다.

- Java 17 이상 (개발 환경 JDK 21)
- Spring Boot 3.5.6 (전자정부 표준프레임워크 5.0과 같은 기반) + Thymeleaf
- 패키지 구조: 전자정부 프레임워크 방식 `egovframework.haengjeongnuli.{업무}.web / service`

## 실행

```bash
./gradlew bootRun
```

브라우저에서 http://localhost:8080 을 엽니다. Windows에서는 `gradlew.bat bootRun`. 서버 창의 한글이 `泥?愿由ъ옄`처럼 깨져 보이면 PowerShell에서는 먼저 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`, 명령 프롬프트(cmd)에서는 `chcp 65001`을 실행하세요(`scripts/start-all.ps1`로 켜면 자동으로 맞춥니다). `bootRun`은 프로필을 정하지 않으면 local(H2 파일 DB)로 실행합니다.

### 전자민원과 함께 켜기 (Windows)

탐색기에서 `scripts\start-all.bat`를 더블클릭하거나, 행정누리 폴더의 PowerShell에서 한 줄로 둘 다 켭니다.

```bash
powershell -ExecutionPolicy Bypass -File .\scripts\start-all.ps1
```

- 창이 두 개 새로 뜹니다. 행정누리(`https://이PC주소:8443`)와 전자민원(`https://이PC주소:3000`) 모두 이 PC와 **같은 집 공유기에 연결된 휴대폰·노트북**에서 열립니다. 행정누리는 공유기 내부망(사설 주소)에서 오는 접속만 받고, PC가 공유기 없이 공인 주소를 받았으면 이 PC에서만 엽니다. 이 PC에서만 열려면 `scripts\start-all.bat -ThisPcOnly`. 열 주소를 화면에 알려 줍니다.
- **집 밖 인터넷에서 쓰기:** `scripts\start-all.bat -Internet -PublicHost myhome.iptime.org` 로 켜고 공유기에서 포트포워딩(3000·8443 → 이 PC)을 합니다. 행정누리는 집 밖에서 **2단계 인증(OTP)을 켠 직원만** 쓸 수 있으니 집 안에서 먼저 '내 보안'에서 켜 두세요. 다 쓰면 `-Internet` 없이 다시 켜서 닫으세요.
- 오가는 비밀번호·개인정보를 가로채지 못하게 둘 다 HTTPS 로 켭니다. 이 PC 전용 시험 인증서(`data\tls\haengjeongnuli.cer`)라서 처음에 "안전하지 않음" 경고가 뜹니다. 경고를 없애려면 그 파일을 휴대폰·PC에 인증서로 설치하세요.
- 두 프로그램이 같이 쓰는 비밀값은 `data\epetition-secret.txt`에 처음 한 번 무작위로 만들어집니다(저장소에 올라가지 않음).
- 전자민원 폴더는 행정누리 폴더 옆·안, 내려받기·바탕화면에서 `haengjeongnuli-e-Petition`으로 시작하는 폴더(zip으로 받아 이름 뒤에 `-main` 등이 붙은 것 포함)를 찾아 씁니다. 찾은 두 폴더를 화면 첫 줄에 보여 줍니다.
- 그래도 못 찾으면 `-EPetitionDir C:\경로\haengjeongnuli-e-Petition`을 붙입니다.
- 지울 때 `data` 폴더를 통째로 지우면 비밀값도 새로 만들어지는데, 두 프로그램을 이 스크립트로 같이 켜면 문제없습니다.

로컬 DB를 처음 상태로 지우려면 서버를 끄고 프로젝트 폴더의 `data` 폴더(와 올린 파일 `uploads` 폴더)를 지운 뒤 다시 실행합니다.

## 로그인

- 처음 실행해서 계정이 하나도 없으면 **첫 관리자 계정 `admin`**을 만들고, 비밀번호를 **`data/initial-admin-password.txt`** 파일에 적습니다(서버 창에는 파일 위치만 나옴). 로그인하면 비밀번호를 바꾸게 되고, 바꾼 뒤 그 파일을 지우세요.
  - 비밀번호를 직접 정하려면 처음 실행 전에 환경변수 `APP_INIT_ADMIN_PASSWORD`를 넣습니다.
- 관리자는 머리글의 **계정 관리**(`/admin/users`)에서 직원 계정을 만들고, 부서 이동·잠금 해제·사용 중지·비밀번호 재설정을 합니다. 부서 이동은 `USER_DEPT_HISTORY`에 이전·새 부서, 처리자, 시각이 남고 화면 아래 '최근 부서 이동'에서 볼 수 있습니다.
- 권한: 일반 직원 / 창구 직원(민원 접수 가능) / 시스템 관리자(계정 관리, H2 콘솔)
- 비밀번호는 BCrypt로 암호화해 `USER_ACCOUNT` 테이블에 저장합니다. 규칙: 9자 이상, 영문·숫자·특수문자 포함, 아이디 포함 불가 (`PasswordPolicy`에서 변경)
- 비밀번호를 5번 틀리면 계정이 15분 동안 잠기고 저절로 풀립니다(관리자는 바로 풀 수 있음). 한 PC에서 10분에 20번 틀리면 그 PC의 로그인을 잠시 막습니다.
- 관리자가 계정을 사용 중지하거나 비밀번호를 재설정하면 그 사람의 로그인 중인 화면도 바로 로그아웃됩니다. 담당·부서를 바꾸면 다시 로그인하지 않아도 바로 반영됩니다.
- 모든 등록·수정 요청에 CSRF(요청 위조) 확인을 합니다.
- DB를 직접 보는 H2 콘솔(`/h2-console`)은 기본으로 꺼져 있습니다. 필요할 때만 `$env:H2_CONSOLE_ENABLED="true"`를 넣고 실행합니다.
- **비밀번호 변경 주기**: 마지막으로 바꾼 지 90일(`app.password.max-age-days`)이 지나면 다른 화면으로 가지 못하고 비밀번호 변경 화면으로 이동합니다. 관리자가 만들거나 재설정한 비밀번호는 첫 로그인 때 바로 바꿔야 합니다. 이 기능 전에 만든 계정도 다음 로그인 때 한 번 바꾸게 됩니다.
- **접속·작업 기록**: 로그인 성공·실패, 로그아웃, 비밀번호 변경, 계정 관리, 글·댓글 등록·수정·삭제, 첨부파일 내려받기, 민원 접수를 누가·언제·어느 IP에서 했는지 `AUDIT_LOG`에 남깁니다. 관리자는 **계정 관리 › 접속·작업 기록 보기**(`/admin/audit`)에서 직원·작업 종류·기간으로 찾아봅니다.
- **알림**: 머리글의 종 모양 버튼에 읽지 않은 알림 수가 보입니다. 지금은 내 글에 댓글이 달리면 알림이 옵니다. 알림을 누르면 읽음으로 바뀌고 해당 화면으로 이동합니다.

## 접속 허용 범위

기본값으로 **이 PC에서만** 접속할 수 있고, 다른 기기에서 오는 접속은 로그인 화면도 보여주지 않고 막습니다. 막힌 접속은 서버 창에 기록됩니다.

- 범위는 `application.yml`의 `app.access.allowed-networks` 또는 환경변수 `APP_ALLOWED_NETWORKS`로 바꿉니다 (CIDR, 쉼표 구분).
- 집이나 사무실의 **다른 기기에서도** 쓰려면 그 대역을 넣습니다 (예: 공유기 대역 192.168.0.x):

```powershell
$env:APP_ALLOWED_NETWORKS="127.0.0.1/32,::1/128,192.168.0.0/24"
.\gradlew.bat bootRun
```

- 접속한 기기의 실제 주소만 보며, 요청 헤더(X-Forwarded-For 등)로 주소를 속여도 통과하지 않습니다.
- 함께 지킬 것: 공유기에서 8080 포트를 **포트 포워딩하지 않기**, Windows 방화벽에서 Java를 **'개인 네트워크'만 허용**하기.

## 데이터베이스

데이터 접근은 MyBatis(SQL은 `src/main/resources/egovframework/mapper/`)로 하며, Oracle·Tibero·H2에서 모두 도는 Oracle 문법만 씁니다.

| 실행 방법 | DB | 비고 |
|---|---|---|
| `./gradlew bootRun` | H2 파일 DB (Oracle 호환 모드) | 기본값. 프로젝트의 `data/` 폴더에 저장. 테이블 자동 생성 |
| `--spring.profiles.active=oracle` | Oracle | `ojdbc11` 드라이버 포함 |
| `--spring.profiles.active=tibero` | Tibero | 드라이버 jar를 `libs/`에 직접 넣어야 함 |

로컬 H2 데이터는 `$env:H2_CONSOLE_ENABLED="true"`로 실행했을 때 http://localhost:8080/h2-console 에서 볼 수 있습니다 (시스템 관리자만, JDBC URL: `jdbc:h2:file:./data/haengjeongnuli;MODE=Oracle;AUTO_SERVER=TRUE`, 사용자 `sa`, 비밀번호 없음).

### Oracle / Tibero 운영 준비

실제 Oracle 서버에서는 아직 실행해 보지 못했습니다. 아래 점검은 H2의 Oracle 호환 모드와 정적 검사로 했으므로, 운영 전에 시험 DB에서 한 번 돌려 보세요.

**이미 점검한 것**

- 새로 설치(`schema.sql`)한 구조와, 예전 구조에 `migration/002~037`을 순서대로 적용한 구조가 테이블·컬럼·형식·길이·NULL 여부까지 같습니다(785개 항목). 로컬 H2 구조와도 같습니다.
- 글자 컬럼은 모두 `VARCHAR2(n CHAR)`(글자 단위)입니다. Oracle 기본값은 바이트 단위라 한글(3바이트)이 화면에서 허용한 길이만큼 들어가지 않는 문제가 있었습니다. 4000바이트를 넘던 5개 컬럼은 1300자로 줄였습니다.
- 컬럼 이름에 Oracle 예약어가 없고, SQL에 Oracle에 없는 문법(LIMIT, ILIKE 등)이 없습니다. Oracle에서 시각까지 들어가는 `CURRENT_DATE` 비교와 집계 함수 안 서브쿼리는 고쳤습니다.

**1. 계정과 권한** — `db/oracle/accounts_and_grants.sql` (DBA가 실행)

- `HJN_OWNER`: 테이블·시퀀스의 주인. 설치·마이그레이션 때만 씁니다.
- `HJN_APP`: 프로그램이 접속하는 계정. `CREATE SESSION`과 테이블 읽기·쓰기(SELECT/INSERT/UPDATE/DELETE), 시퀀스 SELECT만 받습니다. 기록물 등록대장(`DOC_REGISTRY`, `DOC_REGISTRY_FILE`)은 SELECT·INSERT만 주어 프로그램에서도 고치거나 지울 수 없습니다. DBA·RESOURCE 같은 관리자 권한은 주지 않습니다.
- 프로그램은 `ALTER SESSION SET CURRENT_SCHEMA`로 `HJN_OWNER`의 테이블을 씁니다(`DB_SCHEMA`).

**2. 테이블 만들기** — `HJN_OWNER`로 접속해서

- 새로 설치: `db/oracle/schema.sql`
- 이미 설치: `db/oracle/migration/` 파일을 번호 순서대로 한 번씩 (`014_char_semantics.sql`은 글자 단위로 바꾸는 것이라, 길이를 줄이는 5개 컬럼에 더 긴 자료가 있으면 그 줄에서 멈춥니다)
- Tibero는 같은 스크립트를 쓰고, `client/lib/jar/tibero7-jdbc.jar`를 프로젝트의 `libs/`에 복사합니다.

**3. 실행** — 비밀번호는 파일에 적지 않고 환경변수로 넘깁니다. Windows PowerShell 예:

```powershell
$env:SPRING_PROFILES_ACTIVE="oracle"          # Tibero 는 tibero
$env:DB_URL="jdbc:oracle:thin:@//DB주소:1521/서비스명"
$env:DB_USERNAME="HJN_APP"
$env:DB_PASSWORD="프로그램 계정 비밀번호"
$env:DB_SCHEMA="HJN_OWNER"
$env:APP_ALLOWED_NETWORKS="10.20.0.0/16,127.0.0.1/32"   # 실제 업무망 대역
$env:APP_INIT_ADMIN_PASSWORD="첫 관리자 비밀번호"         # 계정이 없을 때만 쓰고, 첫 로그인 때 바꾸게 됨
$env:APP_COOKIE_SECURE="true"                            # HTTPS 로 운영할 때만
.\gradlew.bat bootRun
```

- `oracle`·`tibero` 프로필에서는 H2 콘솔이 꺼지고, `APP_ALLOWED_NETWORKS`를 정하지 않으면 서버 자신만 접속할 수 있으며, 계정이 없는데 `APP_INIT_ADMIN_PASSWORD`가 없거나 규칙에 맞지 않으면 시작하지 않습니다.

**4. 백업과 복구** (DBA와 정해서 운영)

- DB: Data Pump로 스키마를 매일 내보내기 (예: `expdp HJN_OWNER schemas=HJN_OWNER directory=DATA_PUMP_DIR dumpfile=hjn_%U.dmp logfile=hjn_exp.log`), 기관 정책에 따라 RMAN 전체 백업. 복구는 `impdp`(필요하면 `remap_schema`).
- 첨부파일: DB에는 파일 정보만 있고 실제 파일은 `app.file.upload-dir`(기본 `./uploads`) 폴더에 있으므로, DB 백업과 같은 시점에 이 폴더도 백업합니다.
- 복구 연습: 분기마다 시험 DB에 복구해 로그인·문서·첨부파일 내려받기가 되는지 확인합니다.

### 지금 DB에 저장되는 것

- **민원**: 접수(접수번호 `연도-일련번호` 자동 부여, 처리기한 계산), 목록·검색, 처리 현황 숫자
- **민원 처리**: 목록에서 제목을 누르면 상세·처리 화면(`/civil/{번호}`)이 열립니다.
  - 담당 배정(직원 목록에서 선택, 담당자에게 알림), 처리 이력 기록
  - 처리기간 연장: 시행령 제21조의 사유(협조·현장 확인·천재지변·이에 준하는 사유)로 처리기간 범위에서 한 차례, 민원인 동의 시 한 차례 더. 민원인 문서 통지 확인 필수, 즉시 처리 민원은 연장 불가
  - 접수 30일이 지나면 진행상황 통지 안내(시행령 제23조)와 통지 기록
  - 처리 완료: 결과 구분·내용, 불수용·일부 수용이면 거부 이유와 구제절차 필수, 결과 통지는 문서 원칙(기타민원이나 민원인 요청 시 문자·전화 등) (법 제27조)
  - 상세 화면에는 민원인 개인정보가 있어 창구 직원·관리자·처리 부서·담당자·접수자만 보고, 열람할 때마다 접속·작업 기록에 남깁니다.
- **게시판**: 글쓰기, 자료 올리기, 목록·검색, 메인메뉴 공지사항
- **게시글 상세·댓글**: 목록에서 제목을 누르면 내용·첨부파일·댓글을 보는 상세 화면(`/board/{번호}`)이 열립니다. 조회수는 같은 로그인 안에서 한 번만 셉니다. 댓글은 1,000자까지, 댓글 쓴 사람과 관리자만 지울 수 있고(삭제 표시), 목록 제목 옆에 댓글 수가 보입니다.
- **공개 범위**: '우리 부서' 글은 글쓴이와 같은 부서 직원, 글쓴이, 관리자에게만 목록·상세·첨부파일·댓글이 열립니다. 부서는 글을 쓸 때의 부서 기준입니다.
- **페이지**: 게시판 목록은 20건씩 나눠 보여줍니다.
- **게시글 수정**: 글쓴이 본인과 시스템 관리자만 목록의 '수정' 버튼으로 제목·내용·공개 범위·분류·상단 고정을 고치고, 첨부파일을 더하거나 뺄 수 있습니다(자료실 글은 파일 1개 이상 필수). 게시판 종류와 글쓴이는 바뀌지 않으며, 수정한 사람·시각을 기록하고 목록에 '(수정됨)'을 표시합니다.
- **게시물 삭제**: 글쓴이 본인과 시스템 관리자만 목록의 '삭제' 버튼으로 지울 수 있습니다. 실제로 지우지 않고 `DELETED_YN='Y'`로 표시(누가·언제 지웠는지 기록)하며, 목록에서 빠지고 첨부파일도 내려받을 수 없게 됩니다. 이 기능 전에 쓴 글은 글쓴이 아이디가 없어 관리자만 지울 수 있습니다.
- **첨부파일**: 게시판·자료실 첨부파일. 파일 자체는 `app.file.upload-dir`(기본 `./uploads`)에, 원래 이름·크기·받은 횟수는 `ATTACH_FILE` 테이블에 저장. 목록의 파일 이름을 누르면 내려받습니다.
  - 파일당 20MB, 한 번에 100MB까지 (`spring.servlet.multipart`)
  - 올릴 수 있는 형식은 `app.file.allowed-extensions`에서 정합니다 (실행 파일 등은 거부)
  - 서버에는 무작위 이름으로 저장하고, 내려받을 때 원래 이름으로 돌려줍니다

- **전자결재**: 기안 → 검토(최대 4명, 차례대로) → 결재권자. `APPROVAL_DOC`(문서), `APPROVAL_LINE`(결재선), `APPROVAL_FILE`(붙임)에 저장합니다.
  - 결재선은 직원 계정 중에서 고릅니다. 결재할 차례가 되면 그 사람에게 알림이 가고, 차례가 아닌 사람은 결재할 수 없습니다.
  - 반려할 때는 사유를 꼭 적고, 기안자에게 알림이 갑니다. 기안자는 '고쳐서 다시 기안'으로 내용을 옮겨 새로 올릴 수 있습니다.
  - 아무도 결재하기 전이면 기안자가 회수해 임시저장으로 되돌릴 수 있습니다.
  - 결재가 끝나면 문서번호를 `기안부서-연도별 일련번호`(예: 기획예산과-12)로 붙입니다. 번호 형식은 기관의 기록물 등록 기준에 맞게 확인이 필요합니다.
  - '수신자 지정' 문서의 수신자에 우리 시스템 부서 이름을 적으면, 결재가 끝난 뒤 그 부서 직원의 '수신 문서'함에 들어가고 알림이 가며, 부서 직원이 접수합니다.
  - 문서는 기안자, 결재선에 든 사람, 수신 부서, 시스템 관리자만 볼 수 있습니다(임시저장 문서는 기안자만).
  - 메인메뉴 '나의 할 일'의 결재 대기 숫자가 실제 건수로 나옵니다.

- **업무메뉴**
  - 사회복지(`/welfare`, 복지 담당만): 기초생활보장 급여 신청 → 조사 → 결정·서면 통지. 신청일부터 30일, 사유가 있으면 60일(국민기초생활 보장법 제26조), 급여는 신청일부터(제27조), 이의신청 90일 안내(제38조). 열람 기록.
  - 건축·토지(`/building`): 건축신고 5일·심의 등 20일(건축법 제14조 제3항) 민원과 인허가 대장. 착수기한 허가 2년(공장 3년)·신고 1년, 1년 범위 연장(제11조 제7항, 제14조 제5항).

- **인사정보**: 관리자가 **계정 관리 › 인사정보**에서 이름·직급·사번·직렬·임용일·내선번호를 고칩니다. 인사 화면에 바로 보입니다.
- **복무 신청**: 인사 화면에서 연가·병가·공가·특별휴가·출장·시간외근무를 신청하면 전자결재('복무 신청' 문서)로 올라가고, 결재 결과가 신청 결과가 됩니다.
  - 연가 일수는 「지방공무원 복무규정」 제7조 표(1년 미만 11일, 1~3년 15일, 3~4년 16일, 4~5년 17일, 5~6년 20일, 6년 이상 21일)로 1월 1일 현재 재직기간에 따라 계산하고, 그 해 신규 임용은 근무 개월 수에 비례합니다(제7조의2). 휴직 공제·가산 연가·저축 연가는 아직 반영하지 않습니다.
  - 휴가 일수는 토요일·일요일·공휴일을 빼고 세며, 반일(0.5일)도 됩니다. 남은 연가(결재 중 포함)를 넘거나 다른 휴가·출장과 겹치면 신청할 수 없습니다. 병가는 연 60일까지(제7조의5).
- **출퇴근**: 메인메뉴·인사 화면의 출근하기/퇴근하기를 `ATTENDANCE`에 하루 한 줄(처음 출근 시각, 마지막 퇴근 시각, 접속 IP)로 남깁니다. 로그아웃하거나 다른 PC에서 로그인해도 출근 상태가 그대로이고, 자정을 넘겨 일해도 어제 출근 기록에 퇴근이 찍힙니다. 인사 화면에서 달별 출퇴근 기록과 근무 시간을 봅니다.

- **재정(세출)**: 예산 편성 → 승인 → 집행.
  - 예산 과목은 「지방자치단체 예산편성 운영기준」(행정안전부 훈령, 2026. 6. 30. 시행) 그대로 처음 실행할 때 들어갑니다: 기능별 분류 13개 분야 54개 부문(별표 9), 성질별 분류 목그룹 8·편성목 38·통계목 130(별표 11), 세입 장·관·항·목(별표 8).
  - 사업 구조(정책사업 › 단위사업 › 세부사업)는 예산편성과 직원과 시스템 관리자가 만들고, 세부사업마다 소관 부서를 정합니다.
  - 소관 부서 직원이 세부사업 × 통계목별로 금액과 산출근거를 작성해 승인을 요청하면 **예산편성과** 직원이 승인·반려합니다(반려는 사유 필수, 자기 요청은 자기가 승인 불가). 요청·결과는 알림으로 갑니다.
  - **지출은 전자결재 '지출결의'로 합니다.** 문서 종류를 지출결의로 고르면 예산(세부사업/통계목), 지출 금액, 채권자, 지급 방법(계좌이체·현금)을 적습니다. 예산 화면의 '지출결의 작성' 버튼으로 바로 시작할 수도 있습니다.
    - 우리 부서 소관의 승인된 올해 예산에서만, 지출 가능 잔액(예산액 − 집행액 − 결재 중인 지출결의) 안에서만 올릴 수 있습니다(지방회계법 제29조 제2항, 같은 법 시행령 제33조).
    - 마지막 결재 때 잔액을 다시 확인하고, 결재가 끝나면 그 금액을 예산 집행으로 기록합니다(결재 문서번호 연결).
    - 잘못된 집행은 지우지 않고 예산편성과가 취소 표시를 남깁니다.
  - 금액은 「행정업무의 운영 및 혁신에 관한 규정 시행규칙」 제2조 제2항대로 `금113,560원(금일십일만삼천오백육십원)` 형식으로 보여 줍니다.
  - 예산 승인 부서 이름은 `app.finance.budget-dept`(기본 `예산편성과`)에서 바꿉니다.
- **세입**: 시스템 관리자가 **세입 담당**으로 지정한 직원만 세입 화면을 엽니다(계정 관리의 '세입 담당 지정'). 세입 목별 예산을 작성해 승인을 요청하면 예산편성과 소속 세입 담당 직원이 승인하고, 수납을 기록해 수납률을 봅니다.

- **관인**: 관리자가 올린 관인 이미지를 시행문에 찍습니다. 관인대장 관리와 행정전자서명은 없습니다.
- **기록물 이관**: 이관 목록(CSV)만 만듭니다. 이관 시기는 법령에서 확인하지 못해 기관 기록관리 기준을 따르도록 했습니다(일부 기관 규정은 보존기간 기산일부터 2년 이내).
- **증명 발급**: 증명서는 주민등록·인감 전산 시스템에서 발급하고, 여기는 발급대장과 수수료 기록만 합니다. 수수료(등·초본 400원, 이해관계인 500원, 인감 600원)는 지자체 안내 기준이며 조례·면제 대상은 기관 기준으로 확인하세요.
- **계약·구매**: 계약대장, 견적 비교, 검수, 물품대장이 있습니다. 입찰·전자조달(나라장터) 연계, 계약보증금 비율 자동 계산, 분할 납품(여러 번 검수)은 없습니다. 검수는 같은 부서의 다른 직원이 하도록 했습니다(기관에서 검사공무원을 따로 정하면 알려 주세요).
- **한글 서식 채우기**: 서식의 누름틀(이름 있는 필드)만 채웁니다. 누름틀이 없는 서식은 한글에서 누름틀을 넣고 이름을 정해 다시 올려야 합니다. HWPX는 내려받기·보기만 됩니다. 가족관계·기본증명서·등·초본 같은 법정 증명서 서식은 위조 방지를 위해 채워 만들기를 막았습니다. 채운 파일은 테스트에서 hwplib으로 다시 읽어 확인했고 한글 프로그램으로는 열어 보지 못했습니다.
- **보안 프로그램 안내**: 직원이 설치했다고 누른 기록일 뿐, 웹 화면은 PC에 실제로 설치됐는지 알 수 없습니다. 실제 점검은 기관의 PC 보안 점검 도구로 하세요. 설치 파일은 이 시스템에 올리지 않고 기관 배포 서버 주소(http/https)만 적습니다.
- **추경·이월**: 지방의회 의결 등 실제 절차를 마친 결과를 반영하는 기능입니다. 계속비 이월은 없습니다.
- **아침 알림**: 서버 한 대 기준입니다. 여러 대로 운영하면 같은 날 두 번 실행되지 않도록 기관 정보 표의 실행 날짜로 막지만, 동시에 시작하면 겹칠 수 있습니다.
- **본문 꾸미기**: 글자 크기·굵게 같은 서식은 없고 항목 들여쓰기와 표만 됩니다(HTML을 받지 않아 안전합니다).
- **한글 문서 보기**: 글자와 표만 옮겨 보여 줍니다. 그림·글꼴·쪽 모양은 없고, 암호가 걸린 문서는 볼 수 없습니다. HWP는 hwplib(Apache-2.0), HWPX는 직접 읽습니다(외부 엔티티 끔, 크기 제한).
- **한글 문서 만들기**: 결재 문서·시행문을 HWP 5.0 파일로 만듭니다. 본문의 '|' 표는 한글 표(실선 테두리, 첫 줄 제목 줄)로 들어갑니다. 관인 이미지는 위조 방지를 위해 고칠 수 있는 HWP 파일에 넣지 않고, 관인이 찍힌 시행문은 인쇄 화면으로만 냅니다. 이 작업 환경에서는 한글 프로그램으로 열어 보지 못했으므로(hwplib으로 다시 읽고 다시 저장해 구조만 확인) 처음 쓸 때 한 번 열어 확인하세요.
- **지출품의**: 계속비·선금급·개산급 정산은 없습니다. 품의 종류별 필수 서류는 기관 기준에 맞춰 보완이 필요합니다.
- **이상 요청 차단**: 점수 기록은 서버 메모리에 있어 다시 시작하면 지워집니다(차단 자체는 DB에 남음). 본문(첨부가 있는 양식)은 검사하지 않아, 공문 내용 때문에 막히는 일은 줄였습니다.
